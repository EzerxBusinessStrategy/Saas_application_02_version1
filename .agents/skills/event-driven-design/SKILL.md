# event-driven-design

Inspect relevant paths, configuration, tests, AGENTS.md, and architecture docs before recommendations. Cite evidence; separate findings from assumptions; use severity where relevant.

Do not change module boundaries, tenant isolation, auth, APIs, queues, caches, billing, audit, databases, or infrastructure. Present options, trade-offs, impacts, approval requirement, and a Proposed ADR.

Output scope, architecture, constraints, evidence-backed findings, alternatives, direction, approval, ADR, and verification checklist.
